# 磁校准引导与覆盖网格

本文是磁校准引导的设计契约：流程怎么走、覆盖网格怎么画、中心和指示怎么算、要从读数接口拿到什么。
播放器侧的算术在 `src/posebridge/coverage.rs`，带单元测试。磁力计读数路径在 PoseBridge 侧进行中，
面板尚未接线，所以这个模块目前只有测试在用；非测试构建里的 `dead_code` 豁免写在 `posebridge.rs`
的模块声明处，接线时一并删掉。

## 现状与边界

Maintenance 页的“校准与参考方向”分栏里有 `MagStart`，结束靠连接栏里的 **End calibration**（`MagStop`）。
`service.rs` 的 `observe_magnetic` 维护锁存：写入尝试过的 `mag_start`（包括结果不确定的）和回读到的
`calsw == 7` 都会锁存，只有回读验证成功的 `mag_stop` 能清除。锁存期间只放行原设备的 `MagStop`、
`Inspect` 与停止；Connect、Apply 和安装检查都用不了，退出也会被拦下。

播放器看不到传感器的标定，眼下也看不到磁场：已验证的几种输出格式都不带磁场字段，而且有两道门是播放器
自己设的——连接路径回读到 `calsw == 7` 时拒绝开始采集，样本又只在 `Phase::Tracking` 下摄取。
现有的引导只有 `command_effect` 里一句 “Follow the sensor's physical calibration procedure”。

## 流程

**开始前。** 先说清三件事：跟踪和声音会停；只能显式结束，不会超时，回读确认结束之前不许退出；不发 SAVE。
再给三条准备：

- 传感器留在耳机上。耳机驱动单元的磁铁是要被一起标定进去的硬铁，拆下来单独校准，装回去就又错了。
- 把耳机摘下来，在手里慢慢转。颈部够不到的方向太多：在磁倾角较大的地区，戴在头上根本填不满顶行。
- 离钢制桌架、显示器支臂、音箱、手机和笔记本一米以上，否则它们会被当成地磁标定进去。

同时显示安装状态和“再做一次安装检查”的入口：网格按耳机轴绘制，安装错了，每一条指示都会指反。

**校准中。** 顶部警示条带设备名和已用时间，**End calibration** 是唯一可用的操作；被禁用的控件就地写出原因。
主体是覆盖网格、目标格和一行指示，旁边是模长离散度和绕三个轴各自累计转过的角度，另有一句
“覆盖不是进度”。

**结束后。** 沿用 sent / readback / completion / persistence 四段词汇，“End verified by readback”
只在回读验证之后出现。然后**再扫一轮**：校准后的离散度只能来自校准后的读数，所以结束校准后要请用户拿同一张
网格再转一遍——原型画布的“结束后”一页直接给出了校准后的数字，漏掉了这一步。前后对比只在两轮都
`complete()` 时出现，覆盖不同的两轮读数，离散度不可比。再往下是播放器自己的拟合中心、醒目的“未保存”和单独
确认的 **Save device settings**，最后引到 Tracking 页的 yaw 回正检查：离散度只说明磁力计读数自洽，是否变成了
稳定的听感，要靠那一步。

“校准前”那一轮从哪来取决于接口（见“对接口的要求与未决问题”第 5 条）：如果校准模式下传感器输出的仍是
旧标定下的值，校准这一轮本身就是“校准前”，用户不必多转；否则要在发出 `MagStart` 之前单独扫一轮。
原型画布上“跟踪 20 秒得到的基线”戴在头上、覆盖不全，与完整的一轮不可比，作废。

## 覆盖网格

方位角 12 列、sin(仰角) 4 行，共 48 格（`COLUMNS`、`ROWS`、`CELLS`）。方位角从正前方向右量，每列 30°，
第 0 列从正后方起算，所以正前方在网格正中，正后方是左右两条边。行按 sin(仰角) 均分，边界是 ±0.5 和 0，
即 ±30° 与地平线，顶行在上。球面上 dΩ = d(sin 仰角)·d(方位角)，所以每格恰好是 4π/48 sr：
**画满网格就是覆盖了球面**。落在边界上的方向归下方或右侧的格子。

用网格而不用极坐标圆盘，一半是几何语汇：`theme.rs` 把所有圆角设成 `CornerRadius::ZERO`，场景里的 footprint
也是方框。更实在的一半是两根屏幕轴正好是手上的两个动作：横着是“转”，竖着是“翻”。空一列就是“往那边再转
过去”，空一行就是“再往上或往下翻”，圆盘上的空洞还得先在脑子里换算成动作。代价是两极被横向拉开，顶行
和底行各 12 格其实挤在正上方和正下方附近；因为等立体角，计数不失真，方向感靠左侧的角度标注来读。

输入是耳机轴（X 右、Y 前、Z 上）下的磁场。若接口按传感器轴给，用 `headset_axes` 按 `Device::mounting`
的语义换轴：第 i 项是指向头部方向 i（右、前、上）的带符号传感器轴，与安装检查写入的是同一个数组。
不是真旋转的安装（镜像、重复、缺轴、越界）一律拒绝，判据复用 `mounting.rs` 的 `unit` 与 `cross`：
镜像的安装会让每一条指示反向，而网格看上去依然合理。

## 中心

方向必须从中心量。耳机驱动单元的钕磁铁就在传感器旁边，硬铁偏置可以与地磁（约 50 µT）同一量级；不减去
中心，所有读数都挤在偏置方向附近的一小块里，怎么转都填不满。

中心用代数（Kåsa）球拟合。在以读数均值为原点的坐标里，拟合的法方程化为 C·c = Σ|p|²p / 2n，其中 C 就是
读数自己的协方差：同一个矩阵既是要求逆的那个，也回答能不能求逆。`span` = det C / (tr C / 3)³ 除掉了尺度：
均匀球面为 1，覆盖到离中心 30° 的球冠约 0.076，只绕一个轴转出的圆环为 0。低于 `MIN_SPAN`（0.05，暂定，
待真实耳机数据确定）时退回均值：圆环的均值就是环心，方向留在环平面里，单个轴够不到的那几行于是正好空着——
这正是网格要暴露的失败。逆矩阵的各列是 C 各行两两的叉积除以行列式，不需要通用求解器。

之所以要拟合而不是直接取均值：只转没翻的一轮，均值会被拉向已覆盖的一侧。测试里只覆盖上方时，均值偏离真实
中心约 34（地磁取 50），拟合误差低于 1e-6。

每次快照都用当前中心把全部读数重新分箱，所以开头几秒已经点亮的格子可能挪动；那是早先的分箱错了，不是现在的。
读数少于 `MIN_READINGS`（16）时不分箱。一轮最多保留 `MAX_READINGS`（4096）个读数，按 5–10 Hz 够几分钟，
更长的一轮保留最新的。非有限读数一律拒收，一个 NaN 就会挪动整轮的中心。

椭球（软铁）拟合不在骨架里。原型“结束后”一页的 Soft-iron axis ratio 目前没有算法支撑，接线之前要么补上
椭球拟合，要么把这一项拿掉。

## 下一步指示

目标是离最新读数方向最近的空格。指示由“把读数移向目标”的旋转给出，而符号是整件事里最容易错的地方：磁场在
世界里不动，耳机转一个角度，读数在耳机坐标系里就反方向转同一个角度。所以要的旋转是把**目标**转到当前读数处，
轴取 `target × current`；写成 `current × target`，每一条指示都反向，而单看每一步又都“差不多对”。

轴的最大分量决定动作，符号决定方向，正方向沿用 `mounting::Motion` 的定义：绕右轴为正是抬头（Nod），绕上轴
为正是向左转（Shake），绕前轴为正是向右侧倾（Tilt）。`Next::instruction` 给出手持时的措辞。测试
`the_named_motion_moves_the_reading_toward_the_target` 不复用上面的推导，而是在固定磁场里把模拟的耳机绕它
自己的轴按指示转 0.1°，检查读数确实靠近了目标；把叉积的顺序换过来，这条测试立即失败。

两个分量接近时，指示会逐帧来回跳。这归绘制层管：指示保持一小段时间再换，不放进算术。读数恰好在目标的对跖点时
哪个轴都行，任何一转都会更近。

## 模长离散度

对每个已覆盖的格子取模长中位数，离散度 = (最大 − 最小) / 中位数。每个方向一票，在某个方向多停一会儿压不过
其余方向——测试里往一格额外塞 1000 个读数，离散度不受影响；每格取中位数，单个毛刺也左右不了结果。

模长取**原样**读数，不先减中心：地磁强度不随转动变化，剩下的离散就是传感器自己读错的量。这也让离散度的含义
完全取决于接口给的是什么，见下一节。显示用的 3% / 8% 分界是暂定值，同样等真实耳机的数据再定。

## 对接口的要求与未决问题

1. 三轴磁场值，5–10 Hz 就够，不需要高速流。
2. 校准模式下和普通跟踪下都要能取到。播放器侧需要一条只读取数路径绕开前面那两道门，而且这条路径上的任何
   东西都不能进入 `head_tracking` 或渲染器：校准中的姿态不是朝向。
3. 坐标系：若 PoseBridge 像处理姿态那样先套上 mounting，直接用；若按传感器轴给，用 `headset_axes`。
4. **最关键的一条：给的是传感器自身标定之后的磁场，还是原始磁场？**
   - 标定之后：前后离散度对比成立；`Centre::Fitted` 到原点的距离就是剩下的硬铁偏置。
   - 原始：离散度在校准前后不会变，对比不成立。那时需要同时读到设备写入的偏置，用播放器自己的拟合中心去交叉
     核对。覆盖网格两种情况下都成立，因为它自带定心。
5. 校准模式（`calsw == 7`）期间传感器输出的是什么：旧标定、原始还是边校边变，决定校准这一轮能不能兼作
   “校准前”那一轮。

## 视觉

- 圆角一律为 0，与 `theme.rs` 的 `CornerRadius::ZERO` 一致。
- 目标格用四条 INK 发丝线框出，与 `mesh.rs` 的 `add_floor_ring` 是同一个器件；同一时刻只有一个。
- 格线分三级，取自地面尺的分级：格线 `#CFC4B3`（BORDER 向 MUTED 按 `FLOOR_GRID_CONTRAST` 的 0.35 插值），
  中心轴（FORWARD 竖线与地平线）`#7A6B57` 最重，外框沿用 BORDER。
- 格色：未采样用 STAGE；已采样从 ACCENT_SOFT 向 ACCENT 按读数数插值，到 `FULL_AT`（6）饱和，之后不再变，
  免得被读成进度。
- 小字要用加深色。ACCENT、MUTED、SUCCESS 在 BACKGROUND 上只有 3.0、3.1、3.7 : 1，正文字号达不到 4.5 : 1。
  加深版保持色相：`#A85A22`（4.7）、`#7A6B57`（4.8）、`#4E6B51`（5.5）。这对整个应用的小字都成立，不只是
  这个面板。
- `FULL_AT`、离散度分界和颜色属于绘制代码，照 `scene3d/params.rs` 的先例放在画它们的地方，不进
  `coverage.rs`。

## 不可动摇的口径

- 覆盖不是完成度：屏上只有“n / 48”和一张图，不出现百分比进度条。
- 屏上的每个数字都是播放器自己的读数，不是对传感器标定的判决。
- 锁存只能由回读验证成功的 `mag_stop` 清除；计时器不行，用户点“我做完了”也不行。
- 不替用户发 SAVE；保存是结束之后单独确认的一次操作。
- 读数路径不喂 `head_tracking`，也不喂渲染器。

## 骨架的范围

`coverage.rs` 现有：网格与分箱、定心（球拟合与均值退路）、逐格中位数离散度、最近空格与指示、传感器轴到
耳机轴的换算。测试钉住的是设计赖以成立的不变量：均匀球面把 48 格填得一样多，每格中心落回本格，网格方向与
画面一致，`span` 的三个参考值，覆盖不均时拟合仍准而均值不准，单轴转动留下顶行和底行，指示的符号（物理模拟），
手持措辞与 `mounting::Motion` 的正方向一致，唯一的空格就是目标，离散度按原样读数计算且每个方向一票，读数不足
不分箱，滑窗与拒收，按手册记录的安装 `[-2, 1, 3]` 换轴。

尚未做：读数路径与 service 里的只读阶段；带 revision 的控制器（快照只在有新读数时重算）；面板绘制；校准后的
复核扫描与前后两轮的保存和对比；椭球拟合；yaw 回正检查。
